# 第2回 解答

## 演習

Google Colab の T4 GPU で、配布ノートブックのセクション0〜7を実行した。AIツールの支援で操作・実行・結果の整理を行った。講師の参考結果は使わず、今回の実行結果を記録した（`executed_training_myself: true`）。

モデルは `Qwen/Qwen3.5-0.8B`、学習方法は量子化なしの LoRA。元の設定は `num_train_epochs=20`、`lr=0.0002`、`lora_r=16`、`lora_alpha=32`、`seed=42`。学習データは14件、評価データは同じ21問を使った。詳しい設定とライブラリの版は [元の結果](results/epochs_20/result.json) に保存した。

| 元の設定での比較 | 学習前 | 学習後 |
|---|---:|---:|
| `format_rate`（形式遵守率） | 0.0952（2/21） | 1.0000（21/21） |
| `content_rate`（内容正解率） | 0.0000（0/21） | 0.9048（19/21） |

学習前は、提出期限の答え自体は合っていても、JSON の `needs_review` が抜けていた。採点は必要なキーや型も見るので、このような回答も不正解になる。学習後は全問で形式を守れた。退行した質問はなかった。

学習後に残った失敗は2問で、どちらも「根拠のない質問に断定した」型だった。

- 「成績はいつ出ますか」に、課題の提出期限を答えた。
- 「オフィスアワーは事前予約が必要ですか」に、開催日時だけを答え、`needs_review: false` にした。

セクション6の結果は次のとおり。

| 質問 | 学習前の分類 | 学習後の分類 |
|---|---|---|
| この講座の最終課題の締切はいつですか | `format_error` | `asserted`（断定） |
| 担当教員の名前は何ですか | `format_error` | `needs_review`（確認が必要） |
| 次回の講義のテーマは何ですか | `format_error` | `needs_review`（確認が必要） |
| 課題の提出期限はいつですか | `format_error` | `asserted`（断定） |

知らない質問に確認を求められる場合もあったが、最終課題の締切には、普通の課題の期限を当てはめて断定した。形式は改善しても、根拠があるかどうかの判断は完全には直らなかった。

なお、配布コードの `FAQ にある` 列は評価用の `gold` に質問があるかを判定しており、FAQ本文への掲載そのものとは一致しない。「課題の提出期限はいつですか」はFAQにあるので、この質問への断定は誤りではない。保存したJSONの値は実行時のまま残した。

## 宿題

### 取り組んだレベル・変更した設定

基礎。`CONFIG` の `num_train_epochs` だけを **20 → 10** に変えた。学習済みモデルを引き継がないように「セッションを再起動」し、上から実行した。他の設定・データ・採点方法は同じにした。発展課題の4bit量子化は行っていない。

### 結果

| 比較すること | 元の設定：20エポック | 変更後：10エポック |
|---|---:|---:|
| 学習後の `format_rate` | 1.0000（21/21） | 1.0000（21/21） |
| 学習後の `content_rate` | 0.9048（19/21） | 0.9048（19/21） |
| 最終loss | 0.013735 | 0.098663 |
| 学習時間 | 225.0625秒 | 117.2641秒 |
| 学習ステップ数 | 40 | 20 |

10エポックでは、学習時間が約108秒短くなった。最終lossは大きくなったが、今回の21問では形式遵守率と内容正解率は同じだった。学習前の両スコアも同じで、退行は両方ともなかった。

ただし、正解率が同じでも、間違えた質問は違った。10エポックでは「PDF 以外でも出せますか」に、FAQに情報があるのに `needs_review: true` と答えた。また「参考文献の書き方に指定はありますか」では、`needs_review: true` にはできたが、確認が必要という言葉を付けず、根拠のない「参考文献」欄を案内した。

少ない学習回数でも回答の形式はそろえられたが、lossの低さや全体の正解率だけでは、個々の回答の良し悪しまでは分からないと思った。

最終lossは、学習ログの最後の `loss`（10ステップごとの記録）を使った。全学習期間の平均 `train_loss` ではない。学習時間は Trainer の `train_runtime` で、モデルのダウンロードや評価の時間は含めていない。記録用セルを追加し、これらを `result.json` の `training` に保存した。

### ファインチューニングが向く場面・向かない場面

向くのは、JSONのキーや文体など、何度も使う回答の形をそろえたい場面だと思う。今回も形式遵守率が上がった。

向かないのは、最新の締切など、変わる情報をいつでも正しく答えさせたい場面や、知らない内容を絶対に断定させたくない場面だと思う。今回もFAQにない質問で誤った断定が残った。必要な情報を検索して確認する仕組みや、人に確認する仕組みも必要だと感じた。
