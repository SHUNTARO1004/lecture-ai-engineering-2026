# 第3回 解答

## 演習（今回確認した範囲）

- `--trace` で、用語集を検索してから回答する動きを確認した。
- `search_glossary` を `{"query": "LoRA"}` と `{"query": "QLoRA"}` で1回ずつ呼んだ。
- LLM の呼び出し回数（`requests`）は2回だった。
- 今回は宿題の基礎に取り組み、ツールの追加と第1回の回答との比較は行っていない。

## 宿題

### 取り組んだレベル

基礎。

### やったこと

`app/agent.py` の `INSTRUCTIONS` を1行だけ変更した。

変更前：

```text
- 回答の最後に、関係する回（第N回）を示す。
```

変更後：

```text
- 回答は3項目以内の短い箇条書きにし、最後に関係する回（第N回）を示す。
```

モデルは両方とも `gemini-3.5-flash-lite`。ツールのコードと説明文は変えず、同じ質問を変更前後に1回ずつ実行した。

```bash
uv run python -m app.agent --trace "LoRAとQLoRAの違いは？"
```

### 結果

| 比較すること | 変更前 | 変更後 |
|---|---|---|
| ツール名 | `search_glossary` | `search_glossary` |
| 引数と回数 | `LoRA`、`QLoRA` を各1回 | `LoRA`、`QLoRA` を各1回 |
| ツール呼び出し合計 | 2回 | 2回 |
| LLM 呼び出し（`requests`） | 2回 | 2回 |
| 出力トークン数 | 188 | 134 |
| 回答の形式 | 前置きと、LoRA・QLoRAの2項目の説明 | 前置きなしの短い3項目 |
| 関係する回 | 第2回 | 第2回 |

変更前は、LoRAについて低ランク行列やPEFT、学習結果を小さいファイルで保存できることまで説明していた。
変更後は、LoRAの説明、QLoRAの説明、小さいGPUメモリで大きいモデルを扱える利点の3項目にまとまった。
用語集を検索する回数と引数は変わらなかった。
ただし、変更後の「パラメータ数を削減」は「学習するパラメータ数を減らす」と書いた方が正確だと思う。短くなっても、説明の正確さは確認する必要がある。

実行ログ： [変更前](results/before.txt) / [変更後](results/after.txt)

既存テストは `uv run pytest -q` で **11 passed** だった（[テスト結果](results/tests.txt)）。
このテストはプログラムの動作確認であり、実際の回答の良さは上のログで確認した。
